## 1. 背景与问题

用户使用 497 IDML 两版（`497有图.idml` / `497导出_WD注入.idml`）测试对比，仍存在**整段删除和新增**的情况（整段 DEL+ADD），而不是细粒度的标点/字符级 diff。

### 1.1 文件规模实测

| 维度 | A（有图） | B（导出_WD注入） |
|------|-----------|------------------|
| 字符数 | 636,223 | 626,500 |
| 段落数（U+2029 切分） | 1,640 | 1,638 |
| 竖排 | 是 | 是 |

### 1.2 当前 diff 结果

```
diff 耗时: 0.95s
stats: {'total': 21886, 'add': 6931, 'del': 14933, 'mod': 22}
LCS 对齐: {'eq': 613, 'del': 1027, 'add': 1025}
替换组: fine(字符级)=204 组 | coarse(段落级)=116 组
coarse 组中标点归因成功(实词相同)=101/116
```

## 2. 根因分析（三层）

### 2.1 根因 1：段落 LCS 用精确哈希

`diff_texts_para_lcs` 用 `MD5(段落原文)` 做段落对齐。497 两版之间：

- 原文精确匹配：**634/1640 段（38.7%）**
- 去标点+空白+U+2029 后匹配：**1635/1640 段（99.7%）**

→ 1006 段实际上只有标点/空白差异，却被判为"不同段"，进入替换组。

### 2.2 根因 2：替换组超 4096 字符上限 → coarse 分支

320 个替换组中：
- 204 组 ≤ 4096 字符 → fine（组内字符级 DMP）
- 116 组超限 → coarse：
  - 101 组标点归因成功（`_coarse_punct_alignment` 检测到实词相同，输出细粒度）
  - **15 组标点归因失败 → 整段 DEL+ADD**

### 2.3 根因 3（关键 bug）：`_strip_sep` 不剥离 U+2029

15 个"真重写"组中，**2 组（组 3、组 15）实词实际完全相同**，差异仅在 U+2029 的位置。但：

- `_strip_sep` 只剥离 `_PUNCT_CHARS` 和 `_WS_CHARS` 中的字符
- **U+2029（段落分隔符）既不在标点集也不在空白集** → 被当实词保留
- 实词串含 U+2029 → 比较结果不同 → 判"实词不同" → 放弃标点归因 → 整段 DEL+ADD

**影响面**（经验证）：
| 函数 | 路径 | 影响 |
|------|------|------|
| `_strip_sep` | L3 + coarse 实词比较入口 | 实词串含 U+2029 |
| `split_by_sep`（L3） | `_resolve_punct_alignment` 间隙对齐 | U+2029 被当实词字符 |
| `split_by_sep`（coarse） | `_coarse_punct_alignment` 间隙对齐 | 同上 |
| `stripSep` / `splitBySep`（前端） | 编辑模式 diffSafely | 同上 |

### 2.4 15 组真重写的实际分类

| 类别 | 组数 | 说明 |
|------|------|------|
| U+2029 误判（可修复） | 2 | 实词完全相同，仅段落分隔符位置差异 |
| 真实段重排/重写 | 13 | 经卷顺序调整、经名变更、内容重排（实词 ratio 0.01~0.73） |

13 组真实重写中，大部分是**经卷内容在不同位置重新出现**（如"中阿含經卷第三十七"的内容在 A 版某位置、B 版另一位置）。段落级 DEL+ADD 对这种场景语义合理。但其中 2 组经归一化 LCS 对齐后实词相同（仅标点不同）→ 方案 B 可细粒度化。

## 3. 方案 A：U+2029 归因修复（独立交付）

### 3.1 改动清单（5 处，后端 3 + 前端 2）

| # | 文件 | 函数 | 改动 |
|---|------|------|------|
| 1 | `src_backend/diff_engine.py` L51 | `_strip_sep` | `c not in _PUNCT_CHARS and c not in _WS_CHARS and c != _SEP` |
| 2 | `src_backend/diff_engine.py` L195 | `split_by_sep`（L3 `_resolve_punct_alignment` 内） | `c in _PUNCT_CHARS or c in _WS_CHARS or c == _SEP` |
| 3 | `src_backend/diff_engine.py` L308 | `split_by_sep`（`_coarse_punct_alignment` 内） | 同上 |
| 4 | `src/render/unicode.ts` L277 | `stripSep` | `!PUNCT_CHARS.has(c) && !WS_CHARS.has(c) && c !== "\u2029"` |
| 5 | `src/render/unicode.ts` L266 | `splitBySep` | `PUNCT_CHARS.has(c) \|\| WS_CHARS.has(c) \|\| c === "\u2029"` |

### 3.2 设计说明

- **U+2029 是段落结构符，不是内容字符**。它由 IDML 解析器 `<Br/>` 映射而来（`idml_parser.py:431`），在 diff 语义上应视为分隔符（与标点、空白同族）。
- **不修改 `_WS_CHARS`**：若把 U+2029 加入空白集，W 归因会把孤立 DEL U+2029 隐藏、DEL U+2029+ADD 标点折叠——导致段落合并/拆分不可见。保持 U+2029 在 `_PUNCT_CHARS`/`_WS_CHARS` 之外、仅在 `_strip_sep` 和 `split_by_sep` 中特殊处理，**段落分隔符的增删保持可见**（结构变化应当可见）。
- 影响范围：
  - L3 `_resolve_punct_alignment`（全局 DMP 路径）：修复多段落替换组内的标点归因
  - `_coarse_punct_alignment`（段落 LCS coarse 分支）：修复 U+2029 误判
  - 小文档（<150K 字符，无 U+2029）不受影响
  - 前端编辑模式（`diffSafely`）：同步修复

### 3.3 预期效果

- 15 组真重写 → **13 组**（2 组 U+2029 误判修复）
- 耗时不变（0.95s）
- 重建校验不受影响

### 3.4 测试

- 新增单测：
  - `_strip_sep` 剥离 U+2029（"abc\u2029def" → "abcdef"）
  - L3 对含 U+2029 的替换组正确归因（X="abc\u2029def", Y="\u2029abcdef" → 间隙对齐）
  - coarse 对含 U+2029 的组正确归因
  - 前端 `stripSep`/`splitBySep` 同步用例
- 回归：全量测试（后端 113 + 前端 122）

## 4. 方案 B：归一化哈希段落 LCS（依赖方案 A）

### 4.1 核心思路

段落 LCS 的 eq 判定从**原文精确哈希**改为**归一化哈希**（剥离标点+空白+U+2029 后 MD5）。只差标点的段落直接对齐为 eq，不再进入替换组。

### 4.2 关键实验决策：段对处理用间隙对齐，不用 DMP

对 1021 个"归一化对齐但原文不同"的段对实测：

| 指标 | 间隙对齐（`_coarse_punct_alignment`） | 段内 DMP（`_diff_fine_group`） |
|------|----------------------------------------|-------------------------------|
| 耗时 | **0.33s** | 1.50s（4.5 倍） |
| mod 段 | **8** | 35 |
| 失败数 | **0** | 0 |
| del 字符 | 16532 | 16560 |
| add 字符 | 7594 | 7579 |

**结论**：间隙对齐更快、mod 更少、0 失败、字符量几乎一致。**段对处理必须用间隙对齐**（`_coarse_punct_alignment`），不能走 DMP（DMP 的 `cleanupSemantic` 会把标点+实词局部变更合成更多 mod 段）。

### 4.3 改动清单（5 处，仅后端）

| # | 位置 | 改动 |
|---|------|------|
| 1 | `diff_texts_para_lcs` 新增 `_strip_all` | 复用修复后的 `_strip_sep`（剥离标点+空白+U+2029） |
| 2 | `diff_texts_para_lcs` 双哈希 | `ha_raw/hb_raw`（原文 MD5）+ `ha_norm/hb_norm`（`_strip_all` 后 MD5） |
| 3 | LCS DP eq 判定 | `ha_norm[i] == hb_norm[j]`（替代原文哈希） |
| 4 | 组装阶段 eq 处理 | 若 `ha_raw[ai] != hb_raw[bi]`（原文不同）→ `_coarse_punct_alignment(pa[ai], pb[bi])` 间隙对齐；返回 None 则回退 `_diff_fine_group`（兜底） |
| 5 | 重建校验 | A 侧 `_strip_ws`（允许空白差异，与 W 归因一致）；B 侧精确 |

### 4.4 边界情况（已验证）

| 边界 | 实测 | 处理 |
|------|------|------|
| 归一化后为空的段落 | A=223, B=224（纯 `\u2029` / `\u3000\u2029` 段） | LCS 空段对齐空段正确；间隙对齐可处理（如 `\u2029` vs `。\u2029` → 2 段） |
| 归一化哈希重复 | 25 组（"東晉罽賓三藏瞿曇僧伽提婆譯"等重复模板段） | 内容相同，LCS 贪心对齐无副作用 |
| 空归一化段对（两侧原文不同） | 20 个 | 间隙对齐全部可处理，0 回退 DMP |
| 单段超长（max 9499 字） | 段对中最大单段 9499 字 | 间隙对齐 O(n)，无超时风险 |

### 4.5 预期效果（497 实测模拟）

**残余 2 组 coarse**：真实内容差异（如"跋陁和利"→"牟犁破羣那"经名替换），段落级展示语义合理。

| 指标 | 修复前基线 | 方案 A | 方案 A+B | 文档预期 A+B | 实测判定 |

关键实现补充（方案 A 增强）：`_align_gap_pair` 间隙公共前缀/后缀对齐——
U+2029 与新增标点相邻（`誦\u2029` → `誦。\u2029`）时，公共部分保持 EQ、
仅差异部分 DEL/ADD，避免整体比较误判为替换（mod 22→15 而非 22→303）。
前后端同步（`unicode.ts` 同构实现）。

### 4.6 权衡说明（用户已确认接受）

1. **stats +2184（21886→24070）**：段对独立展示比 coarse 合并组更细碎的必然结果，语义更准确（每个段落对的变化独立显示），可接受。
2. **25 组重复模板段贪心对齐**：内容相同的重复段，LCS 对齐结果非直觉但无实际影响，可接受。
