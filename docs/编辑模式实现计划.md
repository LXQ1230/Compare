## 1. 项目背景与现状

### 1.1 项目定位

IDML 文档对比工具,支持字符级 diff、编辑模式、导出多格式、IDML 反向写入。当前项目实际支持的文件格式为 `.txt / .docx / .md`(validators.py 限制),IDML 流程状态待确认。

### 1.2 技术栈(已核实,2026-08-03)

- 前端:Vue 3 (Composition API + `<script setup>`) + TypeScript(**`strict: true` 已开启**)+ Vite + Pinia + vue-router
- 后端:Python 3.13 + **FastAPI + uvicorn**(命令行启动,`main.py` 无 `__main__` 入口)
- Diff 引擎:后端 `diff_engine.py` **自研 `diff_texts`**(非 diff_match_patch);diff-match-patch 1.0.5 仅前端 JS 版,供 `editClassifier.ts` 使用
- 编辑器:CodeMirror 6(已集成 `@codemirror/state` + `@codemirror/view`)
- 前端测试:Vitest + jsdom(当前 18/18 通过,仅 `core.spec.ts` 一个文件)
- 后端测试:`tests/unit` + `tests/integration`(历史记录 72/72 通过)

**依赖缺口**(修订确认):`@codemirror/commands`(缺,undo/redo 快捷键无法绑定)、`@codemirror/theme-one-dark`(缺)、`@codemirror/lang-markdown`(缺);`@codemirror/lang-cpp` 已装但**未使用**(待清理)。

### 1.3 编辑模式当前实现状态(截至 42e12c1,2026-08-03 核实)

**已有基础**:
- `CodeMirrorDiff.vue` 基于 CM6,双层 Decoration 系统:`diffField`(原始差异)+ `userField`(用户编辑)
- `buildDecoSet` user 模式已过滤 phantom 段(del/mod-old 不进入文档)(**42e12c1 已修复**)
- `editClassifier.ts` 基于 diff-match-patch 做字符级编辑分类
- 6 色基础类:`cm-add / cm-del / cm-mod-old / cm-mod-new / cm-user-add / cm-user-del`(user-mod 尚无独立类)
- 非编辑模式搜索/Sidebar/J-K 跳转已闭环(`segmentRenderer.ts` 输出 `id="ci-N"` + `data-ci`,`ReportPage`/`Sidebar` 已消费)
- 后端 autosave/version API 已就绪,前端 0 调用
- 视图切换在编辑模式已禁用(ReportPage `v-if` 仅渲染 CM)

**关键缺口**(修订后,优先级最高 5 项):
- ① **编辑模式 J/K、Sidebar、搜索跳转全部失效**:编辑模式下 UnifiedView 卸载,CM 内无 `ci-N` DOM(`ReportPage.scrollToContext`/`Sidebar.scrollTo` 静默空转)
- ② **undo 基线错乱**:`lastBaseline` 在 debounce 中累积更新,用户撤销后基线不回退,"撤销→再编辑"分类错乱
- ③ **编辑模式搜索高亮无法渲染**:UnifiedView 卸载后无 CM 搜索 decoration 层
- ④ 编辑模式导出/自动保存未接入 editorStore(HTML/MD/TXT 三格式都走 `compareStore.segments`)
- ⑤ autosave/version 共 4 个裸 fetch 无任何 timeout(`api.ts` 中 `autosave`/`versionSave`/`versionList`/`versionRestore`,均未走 `fetchWithTimeout`)

## 2. 用户决策记录

通过 4 轮交互式提问 + 5 轮深挖,确认以下设计决策:

### 2.1 编辑模式核心决策(第一轮)

| 维度 | 决策 | 理由 |
|------|------|------|
| 实时性 | 300ms 防抖 + `requestIdleCallback` 兜底 | 大文档性能稳定,肉眼几乎无感 |
| 颜色方案 | 4 色完整体系 | 增、删、改三种行为视觉可区分 |
| 删除显示 | 用 Widget Decoration 显示旧值 | 信息完整,符合 git diff 习惯 |
| 覆盖规则 | 用户层不透明覆盖原始 diff | 被用户触碰的字符只显示用户颜色 |

> ⚠️ **v2 修订注记**:表中"删除显示"与 §2.2 表格存在矛盾(见决策 D10)。当前代码实现为:user-del 仅 mark 删除线,**无 widget**;仅 mod-old 需要 widget。此矛盾待用户拍板后统一。

### 2.2 4 色方案定义(待 B 阶段实现 user-mod 类)

| 操作 | CSS 类 | 颜色 | 视觉特征 |
|------|--------|------|----------|
| 用户新增 | `cm-user-add` | 琥珀黄 (#fff3cd) | 标准背景 |
| 用户删除 | `cm-user-del` | 紫 (#f3e8ff) | 删除线 + 紫底 |
| 用户修改-旧值 | `cm-user-mod-old` | 暖橙 (#fef3c7) | 删除线 + 虚线框 |
| 用户修改-新值 | `cm-user-mod-new` | 暖橙 (#fef3c7) | 加粗 + 边框 |

> 现状:variables.css / EMBED_CSS 仅有 user-add/user-del 两色,user-mod-old/new 变量与类均未定义,待 B 阶段补齐。

## 8. 风险与回滚策略

### 8.1 主要风险(修订版)

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| A2 全量重算与 A9 搜索层联动出 bug | 中 | 高 | 加 try-catch 降级(A10),G1 撤销基线测试覆盖 |
| CM 内跳转通道(A8)与虚拟滚动/长文档兼容问题 | 中 | 中 | 跳转用官方 `scrollIntoView` effect,第三期大文档专项验证 |
| CM6 history 扩展与 user diff 联动出 bug | 中 | 高 | 加 try-catch 降级,单元测试覆盖 |
| Widget 渲染在大文档卡顿 | 中 | 中 | 限制 widget 渲染的字符长度(>1000 字符截断) |
| diff3 算法实现复杂度超预期 | 高 | 高 | 第三期先用半升级方案 |
| Unicode normalization 改变原文 | 低 | 高 | normalization 只在 diff 计算时用,不改原文显示 |
| Web Worker 通信协议设计不当 | 中 | 中 | 用 MessageChannel + Transferable |
| A2 全量重算性能在超大文档退化 | 中 | 中 | 与 A2 同时评估 D5(Worker 提前)的增量成本 |

### 8.2 回滚策略

每阶段独立 git commit,如发现问题:

```bash
# 回滚到第一期开始前
git reset --hard <第一期开始 commit>

# 回滚单阶段
git revert <具体 commit>
```

第一期 7 个阶段(A-G)建议各自独立 commit,便于精准回滚。

### 8.3 兼容性保障(修订版)

- 编辑模式变更不影响 UnifiedView/SplitView 的非编辑状态显示(非编辑跳转仍走 `getElementById`,E3 双通道分支保证)
- ExportDialog 在非编辑模式仍走原 `compareStore.segments` 路径(D1 仅在 `isEditing` 时切源)
- searchStore/Sidebar 在非编辑模式行为不变
- 所有新 CSS 变量加在 `:root`,不破坏现有 variables.css
- A2 固定基线只影响编辑模式内部,不触碰 compareStore 数据
