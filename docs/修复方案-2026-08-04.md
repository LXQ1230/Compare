/** 由两侧全文重建原始对比 segments（与后端 diff_engine.diff_texts 规则一致） */
function buildSegmentsFromTexts(a: string, b: string): Segment[] {
  const raw = diffSafely(a, b);
  const segments: Segment[] = [];
  let ci = 0, i = 0;
  while (i < raw.length) {
    const [op, text] = raw[i];
    if (op === 0) { segments.push({ text, operation: 'none', origin: 'original' }); i++; continue; }
    if (op === 1) {
      if (i + 1 < raw.length && raw[i + 1][0] === -1) {
        ci++;
        segments.push({ text: raw[i + 1][1], operation: 'mod', origin: 'original', side: 'old', ci });
        segments.push({ text, operation: 'mod', origin: 'original', side: 'new', ci });
        i += 2; continue;
      }
      ci++; segments.push({ text, operation: 'add', origin: 'original', ci }); i++; continue;
    }
    if (i + 1 < raw.length && raw[i + 1][0] === 1) {
      ci++;
      segments.push({ text, operation: 'mod', origin: 'original', side: 'old', ci });
      segments.push({ text: raw[i + 1][1], operation: 'mod', origin: 'original', side: 'new', ci });
      i += 2; continue;
    }
    ci++; segments.push({ text, operation: 'del', origin: 'original', ci }); i++;
  }
  return segments;
}

## 7. P2-4 编辑态侧边栏跳转偏移错位 🟠

**根因**：`buildOffsetMap` 基于**编辑前**的 `editSegments` 构建一次，编辑后不更新；且编辑态 Sidebar 的 ci 来自 `editedContexts`（worker 新编号），与 `segOffsets`（原始 ci）不同源。

**修复**：编辑态跳转改为基于 **workerSegments（反映当前 doc）的 doc 偏移**，天然消除偏移错位与 ci 语义差异：

```ts
// CodeMirrorDiff.vue scrollToCi 改造
function scrollToCi(ci: SegmentId): void {
  const v = view;
  if (!v) return;
  if (editorStore.isEditing) {
    // 编辑态：workerSegments 与当前 doc 严格对应（buildDecoSet 同源计算）
    // 缓存过期时同步 flush 一次保证最新
    editorStore.flushEditsSync();
    const segs = editorStore.getEditedSegments();
    const offsets = docOffsetsOf(segs);
    // ci 在 edited segments 中按序匹配（mergeSegments 已全量重编号）
    let acc = 0;
    for (let i = 0; i < segs.length; i++) {
      const s = segs[i];
      if (s.ci != null) {
        acc = s.ci; // ci 单调递增
        if (acc === ci) {
          const offset = docOffsetsOf(segs)[i];
          v.dispatch({ selection: { anchor: offset }, effects: EditorView.scrollIntoView(offset, { y: 'center' }) });
          v.focus();
          return;
        }
      }
    }
    return; // 未找到（该变更被用户删改掉了）
  }
  // 查看态：沿用 segOffsets（大文档查看态 CI 与偏移稳定）
  const target = segOffsets.find((o) => o.ci === ci);
  if (!target) return;
  v.dispatch({ selection: { anchor: target.start }, effects: EditorView.scrollIntoView(target.start, { y: 'center' }) });
  v.focus();
}
```

**性能说明**：`docOffsetsOf` 是 O(n) 遍历（百万段 ~20-40ms，与装饰重建同级），且只在跳转时执行一次；`flushEditsSync` 同步 classify 仅在全量缓存缺失时成本高（百万字 ~几百 ms），缓存存在时为零成本（flush 内部 `fresh === baseline` 短路或重算一次——flush 始终同步重算，建议：**仅当 workerSegments 为空或版本滞后时调用 flush**，否则直接用缓存；见实现细节）。

**注意**：`ci` 匹配用 `editedContexts` 的 index（`asSegmentId(ci)` 从 1 递增）——worker segments 经 `renumberCi` 后 ci 全局连续，与 `editedContexts` 的 index 一一对应，匹配成立。

## 9. P2-8 protectAstral 占位符耗尽 🟠

**修复**：分配器改为显式溢出检测 + 回退无保护 diff（保证**文本不损坏**，仅 diff 粒度可能变粗）：

```ts
// unicode.ts
function protectAstral(text: string, sharedUsed: Set<number>): { text: string; map: Map<string, string>; overflow: boolean } {
  if (!HIGH_SURROGATE_RE.test(text)) return { text, map: new Map(), overflow: false };
  const map = new Map<string, string>();
  let out = "";
  let overflow = false;
  let next = 0xe000;
  for (const ch of Array.from(text)) {
    const cp = ch.codePointAt(0)!;
    if (cp > 0xffff) {
      while (sharedUsed.has(next)) next++;
      if (next > 0xf8ff) { overflow = true; break; }  // 耗尽 → 立即回退
      sharedUsed.add(next);
      const ph = String.fromCharCode(next++);
      map.set(ph, ch);
      out += ph;
    } else {
      out += ch;
    }
  }
  return { text: out, map, overflow };
}

export function diffSafely(baseline: string, edited: string): [number, string][] {
  const sharedUsed = new Set<number>();
  const pa = protectAstral(baseline, sharedUsed);
  const pb = protectAstral(edited, sharedUsed);
  if (pa.overflow || pb.overflow) {
    // 回退：直接 DMP（astral 可能被拆成 surrogate unit，diff 粒度变粗，但文本完整）
    const dmp = new diff_match_patch();
    dmp.Diff_Timeout = 0;
    const raw = dmp.diff_main(baseline, edited);
    dmp.diff_cleanupSemantic(raw);
    return raw as [number, string][];
  }
  // ...原逻辑不变
}
```

**注意**：溢出前已消耗的 `sharedUsed` 状态无副作用（本次调用即弃）。`map` 中已分配的占位符在回退时不使用，无泄漏。

## 12. 实施顺序与回归风险

### 实施顺序（依赖排序）
1. **P1-1 + P2-1**（版本 + 恢复会话，同为 compare store 持久化区域，一起改一起验）
2. **P1-2**（后端独立，无依赖）
3. **P2-6 + P3-8**（同一文件 CodeMirrorDiff/editor 区域）
4. **P2-2 + P2-3 + P2-4**（导航三件套，共享 `docOffsetsOf` 提取与 `compareStore.isLargeDoc`）
5. **P2-7 + P3 后端批**（storage.ts / autosave_manager / version_manager / md_parser / main.py）
6. **P2-8**（unicode 独立）

### 回归风险
- **P1-1 改 `restoreVersionSession`**：重建会话会覆盖当前对比状态——需在调用前确认（版本对话框内"恢复"即用户明确意图，可接受）；`version.ts` 的 `saveVersion` 签名不变，仅调用方传参变化。
- **P2-2/P2-4 引入 `docOffsetsOf`**：两处共用同一偏移计算，必须保证 phantom 段处理一致（不占位），否则搜索高亮与跳转双双错位——建议以 `buildSearchDecos` 现有逻辑为唯一基准并加断言测试。
- **P2-4 flush 性能**：编辑态跳转只在缓存过期时 flush；若百万字文档 flush 卡顿明显，退化为「直接用当前缓存，容忍最多 300ms 的偏移滞后」。
- **P3-2 原子写入**：`os.replace` 在 Windows 跨目录不可用——tmp 与目标同目录（`path.with_suffix('.tmp')` 满足），无此问题。
- **P3-3 正则收紧**：`[ \t]*` 不再匹配换行，可能让「行首带空白的空行 + 编号」场景少删一个换行——属预期修正，golden 测试锁定。
