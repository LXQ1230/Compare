## 标点归因三层防线（diff 语义修复，用户实测）

### 问题（用户实测 497有图.txt / 497有图修改.txt）
- 原「我聞如是」改「我。聞。如是。」，用户意图是「聞」前后各加「。」（2 处新增标点）
- DMP 输出 `DEL 聞 + ADD 。聞。`，把实词「聞」标成 mod（删除线+替换）——语义错误
- 根因：DMP 最小编辑不唯一，"替换实词"与"插入标点"数学等价，DMP 默认选前者；佛经句读场景应优先归因标点

### 方案：三层标点归因防线（前后端同步实现）
- **L1 标点移动**（已有 08-04）：DEL X + 纯标点间隔(≤8) + ADD X → ADD 标点 + X + DEL 标点
- **L2 标点包裹**（本次新增）：DEL X + ADD Y，X⊂Y(Y=P+X+Q) → ADD P + EQ X + ADD Q；Y⊂X → DEL P + EQ Y + DEL Q；两侧须纯标点（含汉字=真替换不重写）
- **L3 实词对齐兜底**（本次新增）：DEL X + ADD Y 紧邻，去标点后实词串相同 → 间隙对齐算法强制标点归因；与前后操作相邻会合成 mod 时放弃重写（保守）
- 收尾 `_merge_adjacent` 合并相邻同类操作

### 实现位置
- 后端 `src_backend/diff_engine.py`：`_resolve_punct_substring` / `_resolve_punct_alignment` / `_merge_adjacent`，diff_texts 内 L1→L2→L3→merge
- 前端 `src/render/unicode.ts`：`resolvePunctSubstring` / `resolvePunctAlignment` / `mergeAdjacent`，diffSafely 同样接入
