## 标点归因三层防线（diff 语义修复，用户实测）

### 问题（用户实测 497有图.txt / 497有图修改.txt）
- 原「我聞如是」改「我。聞。如是。」，用户意图是「聞」前后各加「。」（2 处新增标点）
- DMP 输出 `DEL 聞 + ADD 。聞。`，把实词「聞」标成 mod（删除线+替换）——语义错误
- 根因：DMP 最小编辑不唯一，"替换实词"与"插入标点"数学等价，DMP 默认选前者；佛经句读场景应优先归因标点

### 方案：三层标点归因防线（前后端同步实现）
- **L1 标点移动**（已有 08-04）：DEL X + 纯标点间隔(≤8) + ADD X → ADD 标点 + X + DEL 标点
- **L2 标点包裹**（本次新增）：DEL X + ADD Y，X⊂Y(Y=P+X+Q) → ADD P + EQ X + ADD Q；Y⊂X → DEL P + EQ Y + DEL Q；两侧须纯标点（含汉字=真替换不重写）
- **L3 实词对齐兜底**（本次新增）：DEL X + ADD Y 紧邻，去标点后实词串相同 → 间隙对齐算法强制标点归因；与前后操作相邻会合成 mod 时放弃重写（保守）
- 收尾 `_merge_adjacent` 合并相邻同类操作

### 实现位置
- 后端 `src_backend/diff_engine.py`：`_resolve_punct_substring` / `_resolve_punct_alignment` / `_merge_adjacent`，diff_texts 内 L1→L2→L3→merge
- 前端 `src/render/unicode.ts`：`resolvePunctSubstring` / `resolvePunctAlignment` / `mergeAdjacent`，diffSafely 同样接入

### 问题（用户实测 Word 句读结果）
- Word 句读把「行尾回车/空格 → 标点」作为常规操作，diff 把空白符当内容：

## 草稿恢复性能诊断（用户实测 70 万字"继续编辑"等 5-20s）

### 根因
- `CodeMirrorDiff.ensureEditor` 690-723 行恢复草稿时**主线程同步** `classifyEdit(baseline, editText)`（DMP 全量 diff + 标点管线，`diffSafely` 里 `Diff_Timeout=0` 无超时）→ 70 万字白屏 5-20s
- 正常编辑走 `classifyInWorker`（UI 零阻塞），恢复路径却绕过了 worker——不一致点
- 次因：IDB 读 draft+segments 串行 ~0.3s；装饰重建 ×3 + CM 首屏 ~0.5s

### 方案 B 已定稿（docs/草稿恢复性能优化方案-2026-08-05.md，待实施）
- **核心**：saveDraft 时把 `workerSegments`（用户编辑分类结果）随草稿存 IDB（新字段 `userSegments`），恢复时直接 `buildDecoSet+rebuildDiffLayer`，彻底跳过 DMP diff
- 新鲜度校验：store 加 `workerEditedText`，`workerEditedText === editText` 才存，防存过期结果；缓存未就绪不阻塞保存，恢复回退 worker 异步
- baseline 快照不再剥离（恢复时逐字节复用，天然一致免指纹校验）；localStorage 摘要与后端 autosave 均不存 userSegments（体积约束）
- IDB drafts 为 {key,value} 自由结构，无需 schema 升级；老草稿（无该字段）自动走 worker 回退 + 自愈
- 防御补丁：Diff_Timeout 0→3s；resumeDraft 两次 IDB 读 Promise.all 并行
- 独立问题（后续）：flushEditsSync（导出/侧边栏跳转）主线程同步全量 classify 同样会卡，建议单独一期
- 用户决策：确认方案 B 优先，A（纯异步化）弃用
