## 497 IDML 整段 DEL+ADD 根因分析（讨论阶段）

### 背景
用户反馈 497 IDML 对比仍存在整段删除和新增。用新路径文件（497有图.idml / 497导出_WD注入.idml）实测。

### 实测数据
- A: 636,223 chars / 1,640 段，B: 626,500 chars / 1,638 段
- diff 耗时 0.95s
- stats: total=21886, add=6931, del=14933, mod=22
- LCS 对齐: eq=613, del=1027, add=1025
- 替换组: fine=204, coarse=116
- coarse 中标点归因成功=101，真重写=15

### 三层根因
1. **段落 LCS 精确哈希**：1640 段仅 634 精确匹配（38.7%），去标点+空白后 1635 匹配（99.7%）。1006 段仅标点差异被判"不同段"
2. **替换组超 4096 字符 → coarse 分支**：116 组 coarse，101 组标点归因成功，15 组真重写 → 整段 DEL+ADD
3. **_strip_sep 不剥离 U+2029（bug）**：15 组中 2 组实词实际相同，仅 U+2029 位置不同，但 _strip_sep 未剥离 U+2029 → 误判"实词不同" → 放弃标点归因

### 15 组真重写分类
- 2 组：U+2029 误判（可修复，方案 A）
- 13 组：真实段重排/重写（经卷顺序调整，实词 ratio 0.01~0.73，段落级 DEL+ADD 语义合理）

### 修复方案
- **方案 A（应做）**：_strip_sep 增加剥离 U+2029。1 行改动，修复 2 组误判
- **方案 B（不建议）**：归一化哈希 LCS。eq 613→1634，但 1001 段需段内 fine DMP，耗时 +1.1s，A 重建校验 FAIL，stats 反增（21886→24097）

### 分析脚本

- `scripts/_check_normalized_match.py`：归一化哈希匹配验证

- `scripts/_verify_u2029_impact.py`：U+2029 影响面验证（L3 + coarse + split_by_sep）
- `scripts/_simulate_b_full.py`：方案 B 完整模拟（归一化 LCS + 段内 diff + 重建校验）

### 方案 A（完善后）：修复 _strip_sep 剥离 U+2029
- 改动 3 处（后端 2 + 前端 1）：
  1. 后端 `_strip_sep`：`and c != _SEP`
  2. 后端 `split_by_sep`（L3 + coarse 两处）：`or c == _SEP`
  3. 前端 `unicode.ts`：`stripSep` + `splitBySep` 同步加 U+2029
- 影响范围：L3 `_resolve_punct_alignment`（全局 DMP 路径，多段落替换组）+ `_coarse_punct_alignment`（段落 LCS coarse 分支）
- 小文档（<150K 字符）无 U+2029，不受影响
- 实测效果：15 组真重写 → 13 组（2 组 U+2029 误判修复），耗时无变化，重建校验不受影响
- 风险：极低（1 行逻辑，语义无歧义）

### 方案 B（完善后）：归一化哈希段落 LCS
- 改动 4 处（仅后端）：
  1. `diff_texts_para_lcs` 新增 `strip_all` 函数（剥离标点+空白+U+2029）
  2. LCS DP 用归一化哈希匹配（替代原文哈希）
  3. eq 对齐段原文不同 → 段内 fine DMP（`_diff_fine_group`）
  4. 重建校验改用 `_strip_ws`（A 侧允许空白差异，与现有 W 归因一致）
- 实测效果：LCS eq 613→1634，替换组 320→3，coarse 116→2
- 代价：stats 反增 2211（段内 DMP 比 coarse 标点归因更碎），耗时 0.95s→2.0s
- 重建校验：A(ws_only)=PASS, B=PASS（与当前路径一致）
- 前端无改动（LCS 是后端逻辑）
- 风险：中（LCS 语义变化，需新测试覆盖）

### 关键发现
- 方案 B stats 反增的根因：coarse 路径的 `_coarse_punct_alignment` 已把 101/116 组拯救为细粒度标点 diff；段内 DMP 的 `cleanupSemantic` 反而把标点+实词局部变更合成更多 mod 段
- 方案 B 的真正收益 = 消除"假整段 DEL+ADD"（2 组 U+2029 误判），方案 A 已解决
- 13 组真实段重排在任何方案下都是段落级 DEL+ADD（内容确实在不同位置）

### 方案 B 关键实验结论（2026-08-07 09:59，用户确认方案 B 必做）
- **段对处理方式：间隙对齐（coarse）远优于 DMP**：
  - 1021 段对实测：间隙对齐 0.33s vs DMP 1.50s（快 4.5 倍）
  - mod 8 vs 35（DMP 的 cleanupSemantic 合成更多 mod）
  - 间隙对齐 0 失败（无需 DMP 回退）
  - 字符量几乎一致（del 16532 vs 16560，add 7594 vs 7579）
- 方案 B 完整模拟（间隙对齐版）：stats total 21886→24070（+2184），mod 22→10
- 边界情况全部可控：
  - 归一化空段落 223/224 个（纯 U+2029 / U+3000U+2029 段）——LCS 空段对齐空段正确
  - 归一化哈希重复 25 组（"東晉罽賓三藏瞿曇僧伽提婆譯"等重复模板段）——内容相同无副作用
  - 空归一化段对（两侧原文不同）20 个——间隙对齐全部可处理（如 `\u2029` vs `。\u2029` 输出 2 段）
- **方案 B 最终设计**（依赖方案 A 先完成）：
  1. `_strip_all` 复用修复后的 `_strip_sep`（剥离标点+空白+U+2029）
  2. 双哈希：原文哈希（raw）+ 归一化哈希（norm）
  3. LCS DP 用归一化哈希匹配（eq 判定）
  4. eq 对齐段若原文哈希不同 → `_coarse_punct_alignment` 间隙对齐（不用 DMP）
  5. 重建校验 A 侧用 `_strip_ws`（允许空白差异，与 W 归因一致）
- 预期效果：LCS eq 613→1634，替换组 320→3，coarse 116→2，耗时 0.95→1.3s
- 残余 2 组 coarse = 真实内容差异（如"跋陁和利"→"牟犁破羣那"），段落级合理
- 分析脚本：`scripts/_experiment_b_dmp_vs_gap.py`、`scripts/_check_b_edge_cases.py`

### 实施中关键发现（重要，偏离原方案）
1. **split_by_sep 全改会导致 mod 22→303**：U+2029 作为分隔符后，间隙对齐对 gap 整体比较，`誦\u2029` → `誦。\u2029`（用户只加句号）输出 DEL '\u2029' + ADD '。\u2029' 合成 mod。
2. **新增 `_align_gap_pair` 间隙公共前缀/后缀对齐解决**：公共部分保持 EQ、仅差异部分 DEL/ADD，mod 回落到 15（比基线 22 还低）。前后端同构实现。
3. 只改 `_strip_sep` 不改 split_by_sep 会导致 B 侧重建 FAIL（U+2029 当实词时 cx/cy 长度不一致，间隙对齐错位）——证明方案 5 处改动配套必要，gap 对齐是补足。
4. 方案 B 残余 2 个 coarse 组实词相同（段落合并场景 4段→1段/2段→1段）→ 间隙对齐成功 → 整段 DEL+ADD 实际 0。
